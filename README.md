# Vibemogging 228

Локальный видеоредактор с собственной системой версий изображения и звука.
Коммиты, ветки, сравнение, восстановление и трёхстороннее слияние работают
поверх покадрового представления ролика. Git используется для разработки
приложения; видеорепозиторий имеет собственный формат.

## Статус V1

Интерфейс объединён с ядром в ветке `feature/v1-core`: доступен работающий
прототип редактора. Backend проходит 27 автоматических проверок; объединённая
версия проверена в Chromium с сервером в Ubuntu/WSL.

- Импорт видео, нормализация в фиксированный FPS и экспорт MP4.
- Независимые изменения изображения и звука на выбранном диапазоне.
- Замена видео/аудиофрагмента без изменения длительности, яркость, цвет,
  отключение звука и регулировка громкости.
- Коммиты, ветки, история, восстановление, черновики отдельно для каждой ветки.
- Сравнение по кадрам и PCM-отсчётам, PNG кадра/разницы и WAV для прослушивания.
- Автоматическое объединение независимых правок относительно общей версии.
- Ручное разрешение конфликтов: исходник / наша версия / входящая версия.
- Перенос истории и данных между компьютерами в одном файле `.vmrepo`.

Алгоритм попиксельного слияния подключается через `Repository.pixel_resolver`.
По умолчанию он не задан: конфликтующие кадры требуют ручного выбора.
Конфликты звука также разрешаются вручную. Вставки/удаления со сдвигом
времени и изменение FPS/разрешения существующего проекта относятся к V2.

## Запуск в Ubuntu

Нужны Python **3.11+**, FFmpeg и ffprobe. Python-библиотеки устанавливать не нужно.

```bash
sudo apt install python3 ffmpeg
git clone git@github.com:dmitriifolts54/vibemogging_228.git
cd vibemogging_228
git switch feature/v1-core
python3 -m vibemogging
```

Откройте **http://127.0.0.1:8765**. Сервер доступен только на этом компьютере.
В WSL страницу можно открыть в браузере Windows при работающем перенаправлении
localhost. Остановка — `Ctrl+C` в терминале.

Если папка уже склонирована, повторное клонирование не требуется.
Получение обновлений: `git pull --ff-only` в соответствующей ветке.

Каждая папка данных — отдельный видеорепозиторий. По умолчанию используется
`.vibemogging/` в рабочей папке; она исключена из Git. Для другого проекта:

```bash
python3 -m vibemogging --data-dir ~/videos/another-project --port 8766
```

Приложение блокирует одновременный запуск двух процессов с одной папкой данных.

## Работа на двух компьютерах

1. На первом компьютере импортируйте ролик и сохраните нужные версии.
2. Экспортируйте репозиторий в `.vmrepo` и передайте файл второму участнику.
3. На втором компьютере импортируйте его в пустую папку данных.
4. Каждый участник редактирует локальную копию и сохраняет коммиты.
5. Второй участник экспортирует свой `.vmrepo`; первый импортирует файл
   в исходный проект, выбрав имя участника, например `bob`.
6. Появятся входящие ветки `bob/main`, `bob/имя-ветки`. Объедините нужную
   с текущей веткой. Независимые правки применятся автоматически.
7. Разрешите конфликты, если они есть, и сохраните итоговый коммит слияния.

Для первой передачи репозитория нужен именно `.vmrepo`, а не экспортированный
MP4: файл репозитория сохраняет общую историю и точное содержимое кадров/звука.
Для передачи достаточно файла; отдельный сервер синхронизации в V1 не нужен.

## Воспроизводимый пример

Создать исходный 48-секундный ролик, две независимые копии, правки обоих
участников, файл обмена и проверенный результат слияния:

```bash
python3 -m vibemogging.demo --output-dir /tmp/vibemogging-demo
```

Выберите новую папку: существующая не перезаписывается. Пример проверяет,
что изображение Bob на 00:20–00:25, изображение Alice на 00:30–00:45 и её
звук на 00:20–00:30 включены одновременно, а остальные данные сохранены.
Результаты: `merged.mp4`, `merged.vmrepo`, `report.json` и папки `alice/`, `bob/`.
Для проверки через интерфейс:

```bash
python3 -m vibemogging --data-dir /tmp/vibemogging-demo/alice
```

## Представление данных и слияние

Кадры нормализуются в 8-битный RGB24, звук — в PCM16, 48 кГц, стерео.
Переменный FPS приводится к одному FPS, выбранному при импорте.
Размеры кадра дополняются до чётных; видео без звука получает дорожку тишины.
Это SDR-прототип, сохранение HDR и исходной разрядности не реализовано.

SHA-256 адресует содержимое объектов с учётом их типа. Кадры и звуковые блоки
сжимаются без потерь с помощью zlib. Коммиты ссылаются на неизменяемые манифесты;
они содержат последовательность кадров и аудиоблоков. Одинаковые объекты
повторно не записываются. Метаданные обновляются атомарно.

Видео сравнивается покадрово. Звук хранится блоками по 4096 стереоотсчётов,
но при конфликте блока сравниваются отдельные значения PCM-каналов. Поэтому
независимые изменения внутри одного блока также могут быть объединены.
Границы диапазонов полуоткрытые: `[начало, конец)`.

Близкие аудиоконфликты группируются в участки с промежутками до 10 мс.
Ручной выбор применяется только к конфликтующим значениям; независимые
изменения внутри такого участка сохраняются.

При merge сравниваются общая исходная версия и два результата. Правка только
одной стороны включается; одинаковые правки включаются однократно; разные
правки одной позиции становятся конфликтом. После разрешения создаётся
коммит с двумя родителями. Для истории с несколькими лучшими общими базами
(criss-cross merge) V1 выдаёт явное сообщение о неподдерживаемом случае.

Рабочие изменения хранятся отдельно по веткам и переживают перезапуск.
Восстановление старого коммита создаёт черновик, не удаляя последующие версии.
При активном конфликте редактирование и переключение веток блокируются до
завершения или отмены слияния.

MP4-предпросмотр и экспорт кодируются H.264/AAC и могут отличаться от точного
внутреннего представления. Для совместной работы используйте `.vmrepo`:
повторное сжатие MP4 может изменить даже нетронутые пиксели.

## Ограничения прототипа

- Обработка выполняется на CPU; редактирование и подготовка предпросмотра —
  фоновые операции, не обработка в реальном времени. Статус во время операции
  сразу отдаёт последний согласованный снимок с признаком занятости; чтение
  кадров, аудио и сравнения ждёт завершения изменения репозитория.
- Покадровое хранение заметно объёмнее исходного MP4. Начинайте с коротких
  роликов небольшого разрешения; поддерживаемый предел — 3840 × 2160.
- Одна загрузка ограничена 4 ГиБ. `.vmrepo` содержит полную достижимую историю,
  локальных веток, без инкрементальной передачи. Входящие ветки повторно
  не экспортируются. Для длинных роликов потребуется оптимизация.
- Кэш предпросмотра и недостижимые объекты пока не очищаются автоматически.
- Замена должна покрывать выбранный диапазон; слишком короткий источник
  отклоняется. Конец звука исходного импорта при необходимости дополняется тишиной.
- Нет сетевой совместной сессии, учётных записей, автоматического аудиослияния
  и готового алгоритма попиксельного объединения конфликтующих кадров.

## Проверка

```bash
python3 -m unittest discover -v
```

Тесты не требуют Python-зависимостей. Интеграционные проверки медиа требуют
FFmpeg/ffprobe; без них они пропускаются, а проверки ядра продолжают работать.
Проверяются сценарий диапазонов 00:20–00:25 / 00:30–00:45 / 00:20–00:30,
конфликты, ручное разрешение, сохранение черновиков, перенос между копиями,
дробный FPS, импорт/экспорт, HTTP-загрузки, фоновые задания и byte-range playback.
