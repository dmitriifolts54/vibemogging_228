# Компактное хранение: реализация ядра

Ветка `feature/compact-media-storage`, итерация после V1.
API из [COMPACT_STORAGE_CONTRACT.md](COMPACT_STORAGE_CONTRACT.md) реализован
в `storage.py`, `video_sources.py`, `media.py`.

## Что изменилось

- Исходный сжатый файл копируется в хранилище один раз с адресацией SHA-256.
- При импорте декодирование всё ещё проходит по кадрам для точных RGB-ID,
  но RGB-пayload больше не записывается для каждого кадра.
- Локальный SQLite содержит ссылки: исходник, профиль преобразования и номер кадра.
- При чтении кадр восстанавливается FFmpeg и сверяется с исходным RGB-ID.
- Последовательное чтение использует один поток декодера. Быстрый поиск
  проверяется по хэшу; при несовпадении включается точное чтение с начала профиля.
- Кэш кадров в Python ограничен 32 МиБ; одновременно открыто не более двух
  декодеров на Store. Это лимит именно кэша, не всего процесса FFmpeg/Python.
- Яркость хранится LUT-рецептом; последовательные LUT объединяются без
  создания длинной цепочки эффектов. Заполненные цветом кадры остаются небольшими
  обычными объектами. Звук пока хранится прежними точными PCM-блоками.
- Старые zlib-объекты читаются; их существующие ID и коммиты не меняются.
- `replace_av` заменяет обе дорожки одним действием. Ошибка одной из дорожек
  не меняет исходный манифест. Границы обеих дорожек согласованы с кадрами.

`Store.export_plan()` описывает обычные объекты, рецепты и исходные assets;
экспортёр не должен вызывать `get('video', id)` для материализации всех кадров.
Обычный экспортёр V1 по-прежнему способен раздуть пакет в RGB: обновление
формата обмена до V2 реализуется вторым разработчиком.

## Замер

```bash
python3 -m vibemogging.storage_benchmark --output-dir demo-data/storage-comparison
```

Требуется новая папка. Можно указать собственный исходник через `--source`.
Проверка создаёт оба представления, поэтому старый вариант может потребовать
много места. Измеряется медиаслой, без истории коммитов, MP4-предпросмотров
и скачанных архивов. Не запускайте сравнение большого файла при недостатке места.

25 октября 2026, Ubuntu/WSL, FFmpeg 8.0.1. Генерируемый testsrc2 с шумом:
12 секунд, 1280×720, 25 кадров/с, 300 кадров, со звуком.

| Метрика | Старое хранение | Компактное хранение |
| --- | ---: | ---: |
| Объём на диске, байт | 227 383 454 | 14 819 436 |
| Исходный сжатый файл, байт | — | 13 308 398 |
| Локальный индекс, байт | — | 114 688 |
| Время импорта, с | 16,996 | 2,909 |
| Рост при яркости всего ролика, байт | Не измерялся | 98 539 |

На этом материале объём уменьшился в 15,344 раза. Все исходные и изменённые
кадры сравнивались побайтно со старым представлением. Результат зависит от
исходного кодека, шума и содержания; его нельзя переносить на любой ролик.
Если сам исходный файл уже занимает 115 ГБ, хранение его без перекодирования
сохранит этот объём: нужна отдельная проверяемая lossless-перепаковка либо
явный выбор пользователем сжатия с потерями.

## Интеграционные требования

- Перед публикацией state.json фиксировать рецепты через `store.flush()`.
- При закрытии проекта вызывать `store.close()`.
- Не хранить SQLite в общей синхронизируемой папке; передавать assets и рецепты.
- Пакеты V2, миграция V1, список проектов, облачная папка и UI находятся
  в ветке второго разработчика `feature/compact-projects-cloud`.
- Предпросмотры/экспорты должны иметь отдельный лимит кэша: исправление
  канонического хранения не ограничивает число временных MP4 автоматически.

Нормализация 2 задаёт явный профиль RGB с bitexact-флагами. Независимо от
профиля, кадр возвращается только после совпадения RGB-ID. Отличия декодеров
или повреждение источника вызывают явную ошибку, а не незаметную подмену кадра.

Дополнительные регрессионные проверки покрывают переменный FPS, частоту
30000/1001, дробное смещение источника, открытие сохранённого индекса после
удаления внешней тестовой копии исходника и возврат цепочки эффектов к
первоначальному кадру. Повторно полученный исходник с проверенной контрольной
суммой атомарно восстанавливает повреждённую локальную копию. Чтение старого
репозитория не создаёт в нём новый SQLite-индекс без необходимости.
