# Задача Claude: проекты, обмен и общая папка

Репозиторий: https://github.com/dmitriifolts54/vibemogging_228
База: origin/feature/compact-media-storage
Твоя ветка: feature/compact-projects-cloud

Прочитай docs/COMPACT_STORAGE_CONTRACT.md полностью. Это согласованный контракт
двух разработчиков. Новое API Store и media параллельно реализует основной
разработчик; в первом коммите контракта этих методов ещё может не быть.

Твоя доля — примерно 60–65% текущей работы:

1. Обмен .vmrepo V2, экспорт без распаковки кадров в RGB, импорт V1 и V2,
   проверка assets/recipes, общие export_snapshot/install_snapshot для облака.
2. Безопасная конвертация старых больших репозиториев в новую папку, сохранение
   всей истории/черновиков/конфликтов, lossless-проверка кадров и замер размера.
3. Менеджер проектов и стартовый экран: список, создание, открытие, возврат;
   совместимость с существующим --data-dir.
4. Глобальные проекты через общую папку облачного клиента: неизменяемые файлы,
   отправка только недостающего, снимки каждого устройства, получение и merge,
   защита от неполной синхронизации. Не делай общий изменяемый SQLite/state.json.
5. UI всех новых функций и комбинированной замены replace_av.
6. Тесты интеграции/миграции/обмена/облака/проектов, документация и реальная
   проверка интерфейса с актуальным backend.

Твои файлы: repository.py, server.py, __main__.py, новые workspace/cloud/
maintenance-модули, static/, новые тесты обмена/миграции/проектов/облака,
README и пользовательская документация. Старые тесты можно адаптировать только
по необходимости, сохраняя их смысл.

Не меняй storage.py, media.py, медиаиндекс/декодер основного разработчика,
tests/test_compact_media.py и docs/COMPACT_STORAGE_CONTRACT.md.

Основной разработчик отвечает за компактный Store: исходный сжатый файл один
раз, ссылки на кадры, LUT-эффекты, чтение по запросу, bounded cache и точные
RGB-ID; а также за атомарную замену видео+звука из одного источника.
Координируйся через контракт и регулярно получай обновления базовой ветки.

Причина работы: пользователь сообщил о 115 ГБ для 15 минут в текущем формате.
Нельзя заменять решение снижением разрешения/FPS или незаметным lossy-сжатием.
Нельзя сохранять новый полный MP4/RGB-набор на каждый коммит. Исходные данные
пользователя не удалять и не переписывать. Не обещай коэффициент сжатия без
замеров. Ограничения lossless-перепаковки явно укажи.

Интерфейс на русском, без CDN и сборщика, ошибки показываются честно.
Новые сетевые сервисы, платный хостинг и публичный доступ не нужны: пользователь
выбрал общую папку уже установленного облачного клиента.

Проверь не только happy path: совместные независимые правки, одинаковые кадры,
конфликты и их разрешение, источник+LUT после обмена, неполную синхронизацию,
ошибку конвертации и сохранность исходного репозитория. Для replace_av обе
дорожки меняются вместе; при ошибке одной рабочий проект не меняется.

Если API ещё недоступно, подготовь свою часть по контракту и не переписывай
хранилище. Mock/stub допускается только в изолированных тестах; итоговый код
должен использовать настоящий Store. Не заявляй не выполненные проверки.

Не вливай в main, не используй force-push и не меняй чужие файлы. Сохраняй
промежуточные коммиты и публикуй feature/compact-projects-cloud, чтобы основной
разработчик мог проверить интеграцию. По завершении сообщи хеш коммита,
реализованные маршруты, проверки, замеры, оставшиеся проблемы и нужные изменения
контракта. Основной разработчик объединит и проверит общую версию.
