# Интерфейс V1

Интерфейс — три статических файла в `vibemogging/static/` (`index.html`,
`style.css`, `app.js`). Сборки, CDN и внешних библиотек нет. Страница работает
только с маршрутами из [API.md](API.md) и подходит под CSP сервера: никаких
inline-скриптов и inline-стилей.

## Компоновка

- **Верхняя панель**: проект, выбор ветки, метки «Черновик» и «Слияние»,
  параметры ролика, экспорт MP4, экспорт и импорт `.vmrepo`.
- **Полоса операции**: стадия загрузки или фонового задания и прогресс по
  `GET /api/jobs/ID`. Пока операция идёт, все изменяющие элементы заблокированы.
- **Проигрыватель**: режим «Видео» (кэшированный MP4-предпросмотр) и режим
  «Точный кадр» (PNG без потерь из `/api/frame`). Переход к кадру, шаг ±1 кадр.
- **Таймлайн**: отдельные дорожки изображения и звука, волна звука из
  `/api/audio`, изменённые интервалы черновика и неразрешённые конфликты.
  Щелчок — переход, перетаскивание — выбор диапазона с привязкой к кадрам.
- **Правка диапазона**: начало и конец (`мм:сс.сс`), замена видео или звука
  файлом со смещением, осветление, затемнение, заливка цветом, отключение звука,
  громкость 0–4.
- **Боковая панель**:
  - *Версии* — черновик и его интервалы, сброс с подтверждением, коммит
    с комментарием и автором, история (просмотр, сравнение с рабочей версией,
    восстановление, MP4 версии).
  - *Ветки* — создание, переключение, отметка черновиков, входящие ветки
    `peer/…`, «влить в текущую».
  - *Сравнение* — две любые версии (рабочая, ветка, коммит): интервалы, кадры
    «было / стало / разница» и прослушивание фрагментов звука выбранного диапазона.
  - *Слияние* — запуск слияния, список конфликтов с кадрами или звуком исходной,
    нашей и входящей версий, ручной выбор, завершение коммитом и отмена
    с подтверждением.

## Решения на стороне интерфейса

- Сравнение звука по отдельным значениям PCM может разбить одну правку на много
  соседних интервалов там, где старые и новые отсчёты случайно совпадают.
  Для отображения интервалы с промежутком меньше одного кадра склеиваются.
  Соседние конфликты одного типа показываются одной группой. Выбор для группы
  отправляется отдельным `resolve` для каждого её конфликта, подряд, под одной
  блокировкой.
- `last` в интервалах видео — исключающая граница; показывается как `last - 1`.
- `audio_samples` — число стереоотсчётов: секунды = `audio_samples / 48000`.
- Автор коммита и открытая вкладка запоминаются в `localStorage` этого браузера.
- Восстановление версии при наличии черновика заменяет черновик, поэтому
  интерфейс сначала спрашивает подтверждение.

## Исправления ядра после интеграции

- Близкие аудиоконфликты теперь группируются на backend с промежутками до 10 мс.
  Один выбор применяется только к действительно конфликтующим PCM-значениям,
  сохраняя независимые изменения в промежутках. Это устраняет дробление
  обычной звуковой правки на множество отдельных выборов.
- `GET /api/status` сразу возвращает последний согласованный снимок с `busy: true`
  во время обработки. Страница может показать занятость и дождаться обновления.
  Кадры, звук и сравнение по-прежнему ждут блокировку во время изменения данных.

## Оставшиеся улучшения

Для нескольких раздельных конфликтов интерфейс выполняет последовательные
вызовы `resolve`; каждый может подготовить новый MP4-предпросмотр. Пакетное
разрешение или отложенный рендер могут дополнительно ускорить этот случай.
Изменения контракта для такого расширения пока не внесены.

Результаты проверки совместной сборки: [QA.md](QA.md).
